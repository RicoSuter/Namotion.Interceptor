# DeploymentMatrix [Planned]

Display intended installations and environment-specific details from the shared model.

## Configuration properties [Proposed schema]

This is a proposed widget configuration, not an implemented subject class. Keys use PascalCase for existing Markdown body-block conventions. Each source entry uses the shared [PathQuery](../shared/path-queries.md) record; subject references and collections resolve within the supplied scope.

| Property | Type | Default and meaning |
|---|---|---|
| `Path` | Subject/folder path `string` | Required scope for discovery and relative references. It can select an [Environment](../subjects/environment.md) directly or a tree containing Environments. |
| `EnvironmentSources` | Optional PathQuery list selecting [Environment](../subjects/environment.md) | Omitted: find Environments among the scope and its owned descendants. Empty: select none. Explicit entries select a deduplicated set. |
| `DeploymentUnitSources` | Optional PathQuery list selecting [DeploymentUnit](../subjects/deployment-unit.md) | Omitted: show units selected by the chosen Environments. Empty: show none. Explicit entries filter the units displayed; they do not create installations. |
| `GroupByService` | Optional `bool` | Proposed default `false`. When true, label/group using related [Services](../subjects/service.md), retaining shared or ambiguous membership visibly. It does not change unit identity. |

Read [Deployment](../subjects/deployment.md) subjects generated by each Environment to populate cells. Neither this widget nor its filters generate the Cartesian product of every unit and every Environment. Version/address data comes from the Deployment's authored metadata or supported bindings; observed health requires a separate source.

## Markdown example [Proposed]

Assume `/environments/Staging`, `/environments/Production`, and `/deployment-units/Orders` are authored subjects. This embeds the matrix in any ordinary Markdown page:

````markdown
:: Namotion.ArchDocs.DeploymentMatrix Path=/
```json
{
  "EnvironmentSources": [
    { "Path": "/environments/Staging" },
    { "Path": "/environments/Production" }
  ],
  "DeploymentUnitSources": [
    { "Path": "/deployment-units/Orders" }
  ],
  "GroupByService": false
}
```
::
````

The shorter `DeploymentMatrix Path=/environments` form uses the scoped discovery defaults. Source JSON/frontmatter defining an Environment still uses camelCase fields such as `deploymentUnitSources`; it is separate from this widget configuration.

## Implementation readiness

**Delivery:** Can be implemented through existing subject and component extension points. The ArchDocs feature itself is not implemented.

**Prerequisites:** DeploymentUnits, Environments, generated Deployments, and optional Service grouping.

## Behavior [Planned]

Use explicit Environment selections. Show units against environments, optionally grouped or labeled by related Services. Do not manufacture a Cartesian product of deployments. Link each installation to its subject and expose manual versions/endpoints with provenance.

## Invariants [Planned]

Configured presence does not imply observed health. Missing, unknown, failed, and empty data must remain distinct. An explicit Markdown embed is independent of page-context slots; monitoring connectors are optional future work.
